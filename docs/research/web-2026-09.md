## Claude Code (worker runtime: claude.exe 2.1.275, in the Claude desktop app's folder)

- **Cross-session messaging** (code.claude.com/docs/en/cross-session-messaging)
  - Requires v2.1.234+ on native Windows, and v2.1.248+ on non-Anthropic providers.
  - `ListAgents` and `SendMessage` address a session by the name set with `--name`.
  - `-p` sessions bind an inbox; `--bare` sessions don't.
  - For unattended workers set `crossSessionInbound: "accept"` in `--settings`. A held message otherwise
    expires after `dialogExpiry` (5 minutes).
  - Delivered between tool calls. Plain text, about 1M characters max, 50-message queue, bursts rate-limited.
  - Discovery reads session files under the config dir. *(verified: DeepSeek workers see each other; Claude
    in `~/.claude` does not see them.)*
- **Subagents** (code.claude.com/docs/en/sub-agents)
  - Nest up to 3 levels by default; `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` changes that.
  - Model precedence: the call's `model`, then the agent definition, then `CLAUDE_CODE_SUBAGENT_MODEL`, then
    the parent's model. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` overrides all of them.
  - Subagents inherit the parent's provider env. *(verified: all calls went to `deepseek-flash`.)*
  - They don't inherit allow/deny rules, but settings-file rules still apply to them.
  - Named subagents can `SendMessage` each other and `main`.
- **Agent teams** (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`): not available under `-p`, so not usable for workers.
- **Headless flags** *(verified in `--help`)*: `--name`, `--input-format stream-json`, `--fork-session`,
  `--forward-subagent-text`, `--agents <json>`, `--max-budget-usd`, `--json-schema`, `--mcp-config`.
- **Permission rules** *(verified the hard way)*:
  - `--allowedTools` splits on spaces, so rules naming a path with a space need a settings file.
  - File-write rules are `Edit(...)`; `Write(...)` matched nothing.
  - A Bash rule must match the literal command. MCP tools are allowed by exact name.
- **Hooks**: `PostToolUse` can add `additionalContext` (a possible file-inbox delivery route, not needed now
  that native messaging works). `Stop` can block with a reason.

## DeepSeek Anthropic-compatible API (api-docs.deepseek.com)

- `deepseek-flash` is V4.1 Flash: 1M context, images. `deepseek-v4-pro` is Pro: no images, about 3.3x the price.
  Claude aliases map Opus to Pro and Sonnet/Haiku to Flash, hence the launcher sets every alias to Flash.
- Supported: tools, `tool_choice`, thinking, streaming, images.
  Ignored: `cache_control` (caching is automatic), `anthropic-beta`, `citations`, `mcp_servers`.
  Not supported: PDF document blocks.
- Flash per 1M tokens, peak: cache hit $0.006, miss $0.30, output $1.20. Off-peak is half price; peak is
  01:00-04:00 and 06:00-10:00 UTC on weekdays.
- Concurrency: 2,500 requests per account (Flash), then 429.

## Multi-agent evidence

- **Anthropic, multi-agent research system**
  (anthropic.com/engineering/multi-agent-research-system)
  - Orchestrator plus workers beat a single agent by 90% on breadth-first research. Token spend explains
    about 80% of the variance, and multi-agent runs use about 15x a chat's tokens.
  - Scale effort to the task: 1 agent for simple tasks, 2-4 for comparisons, 10+ for broad research.
  - Workers write outputs to files.
  - Failures: too many subagents, vague briefs causing duplicated work, synchronous waiting.
- **Cognition, "Don't build multi-agents"**: share full context. Parallel agents make conflicting implicit
  decisions.
- **Google Research, scaling agent systems** (arXiv 2512.08296)
  - Centralized coordination: +81% on parallelisable tasks. Multi-agent setups: -39% to -70% on sequential
    tasks.
  - Independent agents amplified errors up to 17x; with an orchestrator, about 4x.
- **MAST** (arXiv 2503.13657): 14 failure modes. Roughly 42% are specification problems, 37% misalignment
  between agents, 21% verification failures.
- **Framework patterns**
  - LangGraph: supervisor, and supervisors of supervisors.
  - CrewAI: hierarchical manager. Practitioners report its manager-worker setup failing.
  - OpenAI Agents SDK: handoffs, against "agents as tools", which keeps the manager in control and is the
    pattern used here.

## Naming and manifest standards

- **OpenTelemetry GenAI agent spans** (github.com/open-telemetry/semantic-conventions-genai; Development status)
  - Span names: `invoke_agent <name>`.
  - Attributes: `gen_ai.agent.id/name/version`, `gen_ai.conversation.id`, `gen_ai.provider.name`,
    `gen_ai.request.model`, token usage.
  - Hierarchy comes from trace and parent span ids.
- **A2A protocol v1.0** (a2a-protocol.org): Agent Card, `taskId`/`contextId`, task states submitted, working,
  input_required, completed, failed, canceled, rejected.
- The manifest (`docs/design/manifest.md`) borrows from both: run id, conversation (session) id, parent and
  root ids, and A2A-style states. It is not an OTel export.
